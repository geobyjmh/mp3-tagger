# Generate MP3 metadata YAML for mp3-tagger

Produce a valid YAML metadata file for the mp3-tagger tool. The model will be given the following inputs (plain text):

album: "<album name>"
artist: "<artist name>"
(Optional) album_art: "<path>"
tracks:
- "Track Title 1"
- "Track Title 2"
- "Track Title 3"

Strict output requirements (the model must follow exactly):
- Output only valid YAML, nothing else. No explanations, no code fences, no comments.
- Top-level properties: optional `album_art` (string) and required `tracks` (array).
- Each track object in `tracks` must include these fields:
  - track_number: integer (1-based)
  - artist: string (use the input artist value)
  - title: string (the track title)
  - album: string (use the input album value)
  - new_filename: string formatted exactly as "NN - Title.mp3" where NN is the zero-padded two-digit track number. Do NOT include the artist in the filename.
- Filenames must be safe (no newlines). Replace or remove characters that are illegal in filenames.
- Do not include additional fields. Follow the schema precisely.

Example input (to supply to the model):
album: "Greatest Hits"
artist: "The Band"
album_art: "cover.jpg"
tracks:
- "First Song"
- "Second Song"
- "Finale"

Expected YAML output (example):
album_art: "cover.jpg"
tracks:
  - track_number: 1
    artist: "The Band"
    title: "First Song"
    album: "Greatest Hits"
    new_filename: "01 - First Song.mp3"
  - track_number: 2
    artist: "The Band"
    title: "Second Song"
    album: "Greatest Hits"
    new_filename: "02 - Second Song.mp3"
  - track_number: 3
    artist: "The Band"
    title: "Finale"
    album: "Greatest Hits"
    new_filename: "03 - Finale.mp3"

Usage note: Provide the input block (album, artist, optional album_art, and tracks list) to the model and instruct it to return only the YAML metadata file described above.
